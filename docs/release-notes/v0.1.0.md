## MCP Detector v0.1.0: first public release

**A safety check for MCP servers, the add-ons you plug into AI assistants.** It connects to a server, looks at what it exposes, and gives it a 0–100 score with every problem explained and how to fix it. It runs on your own computer, sends nothing anywhere, and by default never calls a server's tools.

### Try it

```bash
npx mcp-detector demo              # see a report for a built-in unsafe example
npx mcp-detector ui                # point-and-click web app
npx mcp-detector scan -- node ./build/index.js
```

Not a terminal person? Download the ZIP, install [Node.js](https://nodejs.org) (LTS), and double-click `start-app.bat` (Windows) or `start-app.command` (Mac). Step-by-step guide: [docs/for-beginners.md](https://github.com/adebayomoses/mcp-detector/blob/main/docs/for-beginners.md).

### What it checks (32 rules)

- **Security:** prompt injection and tool poisoning (including obfuscated and base64-hidden payloads), exposed secrets, shell / filesystem / database / network permissions, command injection, plain-HTTP transport, sensitive resources, exfiltration URLs, and **rug pulls** (`mcp-detector pin` records trusted tool definitions and flags any later change).
- **Protocol and schema:** initialization, protocol version, `ping`, invalid or weak input schemas.
- **Quality and performance:** descriptions, duplicates, naming, latency, timeouts, error rate.

### Ways to use it

| | |
|---|---|
| **Web app** | `mcp-detector ui`: demo, paste a command, web address, or pick servers from Claude Desktop / Cursor / VS Code |
| **Command line** | `scan`, `inspect`, `test`, `pin`, `report`, `history`, `badge`, `rules` |
| **GitHub Action** | `uses: adebayomoses/mcp-detector@v1`, with a job summary and a `fail-on` gate |
| **Batch and registry** | `scan-all` for a servers file, your installed MCP apps, or the official registry (remote servers only, passive) |
| **Reports** | terminal, JSON, Markdown, self-contained HTML, SVG badges, a static scoreboard site |
| **Your own rules** | declarative YAML rules, plus opt-in JavaScript plugins |

### Safe by default

- Scans are passive; calling tools is opt-in and limited to tools that look read-only.
- Registry scans never run third-party code and never call tools.
- The web app listens on localhost only, with a private access key, and shows reports in a sandboxed, script-free frame.
- Secrets in command lines and URLs are redacted before anything is stored or published.

### Known limits (please read)

- **A score is a warning light, not a guarantee.** Detection is heuristic: it can flag things that are fine and miss things it was not written to look for. Every finding shows the exact evidence so you can judge it.
- Tested against about ten real servers and a 49-sample attack/benign corpus. False-positive reports are the most useful feedback you can give; there is an issue template for them.
- Developed and tested mainly on Windows; CI covers Linux and Windows. macOS is untested in CI.
- Requires Node.js 22.12 or newer.
